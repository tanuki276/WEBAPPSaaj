# CookAi Web

Android版と配色・カード・操作の案内を揃えたWeb版です。

## 機能
- 食材・料理の種類・難易度・ジャンル・時間・食事スタイル・追加指示からレシピ生成
- メール登録・ログイン・ログアウト・パスワード再設定
- ゲスト履歴を登録アカウントへ引き継ぎ
- Android版と同じFirestore保存先で履歴共有、検索・コピー・共有・全削除
- 調理設定はブラウザ内にアカウントごとに保存

## 配信
VercelでフレームワークOtherとして配信します。ビルドコマンドは不要です。`/api/generate` は既存Cloudflare WorkerへFirebase IDトークンを添えて転送します。AIプロバイダの秘密鍵はブラウザへ配布しません。
`COOKAI_WORKER_URL` で接続先を変更できます。

中継APIの待ち時間は120秒、ブラウザは135秒、Vercel Functionの実行上限は180秒です。複数プロバイダへのフォールバックが30秒を超えても、中継で打ち切らない設定に変更しています。実行上限180秒を使用するにはVercelのFluid Computeを有効にしてください。上流AIの混雑や障害そのものを解消する変更ではありません。

## Firebase
既存の `liefantidia2` プロジェクトを使います。Firebase ConsoleのAuthenticationで匿名認証とメール/パスワード認証を有効にしてください。公開APIキーは既存Android版と同一です。HTTPリファラー等のキー制限がある場合はWebの配信元も許可してください。

Firestoreの保存先は `artifacts/liefantidia2/users/{uid}/history/{id}` です。Androidリポジトリの `firestore.rules` にある、認証済み本人だけが読み書きできるルールを使用します。ルールの公開設定を緩める必要はありません。本作業では本番のFirebase設定・ルールを変更していません。

新規登録は匿名ユーザーにメール認証をリンクしてUIDを維持します。既存アカウントへのログインは別トークンで先にゲスト履歴のコピーを確認し、成功後にセッションを切り替えます。固定ドキュメントIDにより再試行時の重複を防ぎます。コピーが失敗した場合、ゲストの認証と履歴を残します。

ログイン後は履歴をクラウドに保存し、アカウント画面の「履歴を同期する」で他端末の変更を再取得できます。書き込みに失敗した履歴はブラウザに残し、同期時に再送します。クラウドから取得済みの履歴は毎回再送しないため、他端末の削除を復活させません。全削除はAndroid版の履歴にも適用され、実行前に確認します。

未登録のままブラウザデータを削除した履歴は復元できません。登録済み履歴は同じメールで再ログインすると復元できます。調理設定はブラウザ内保存です。

## 確認
`npm run check`：JavaScript構文チェック。
`npm test`：Firebase/Firestoreの通信を模擬し、登録・履歴転送・転送失敗・誤パスワード・APIの時間設定とタイムアウト応答を確認します。本番のアカウントは作成しません。
